# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Planning docs plus a Reveal.js deck for a ~60-90 minute participatory talk teaching mental models
for working with LLMs. The audience includes skeptics and opponents. **Win condition: literacy, not
conversion.** Contested questions (labor, environment, training data, power, "does it understand")
are raised, never settled. When drafting slide text or notes, the main risk is drifting into advocacy.

Read `README.md` (the planning docs) and `deck/README.md` (deck authoring) before substantive work;
they are authoritative and more detailed than this file. If `handoff.md` exists, read it too.

## Commands

```bash
make                              # list targets
make install                      # npm deps: QR code for the remote, rough.js for map generation
make present                      # serve deck/ on :8765 (PORT=...) with the phone-remote relay; prints deck URL + QR
make station NN=02 SLUG=demystify # new slides/02-demystify.md from template, appended to manifest.js
make maps                         # regenerate deck/art/maps/*.svg
```

There is no build, lint, or test step. The deck is static and needs no build; vendored Reveal.js
(`deck/vendor/`) is committed on purpose so it runs offline. Pushing to `main` deploys `deck/` to
GitHub Pages (`.github/workflows/pages.yml`).

## Doc structure (single source of truth)

Each fact lives in exactly one doc; the others link to it. Docs are split by how often they change:
`presentation-arc.md` (stations across cognitive/stance/capability tracks, the backbone) →
`arc-table.md` (per-beat bridge) → `slides-outline.md` (per-slide content) → `deck/slides/*.md`.
Once a station is migrated into `deck/slides/`, that file owns its on-screen text and speaker notes,
and `slides-outline.md` keeps only the visual intent plus a pointer. Artwork specs live in
`metaphor-imagery.md`; unresolved decisions in `open-questions-and-ideas.md` (e.g. Q16 = artwork approach).
Update the owning doc, not a copy.

## Deck architecture

- `deck/index.html` builds one `data-markdown` `<section>` per file in `deck/manifest.js`
  (`window.DECK_STATIONS`, ordered), splitting slides on a lone `---` and notes on `Note:`.
  `slides/art-lab.md` is a prototype sandbox and must be removed from the manifest before presenting.
- Artwork is inline SVG so it can use theme CSS variables and fonts:
  - `art/parts.svg` is a `<symbol>` library inlined at page load; slides place parts with `<use href="#id">`.
  - `<div data-svg="art/...svg" data-zoom="<region>">` inlines a whole SVG after Reveal starts;
    `data-zoom` crops to a region box taken from the SVG's `data-regions` attribute.
  - Colors come from semantic role tokens in `theme/talk.css` `:root` (`--fish`, `--water`, `--land-*`, ...),
    set via `style="fill: var(...)"`, not `fill=` attributes. State changes use empty cue fragments
    and selectors like `.scene:has(.wake-cue.visible)` because CSS can't reach inside `<use>` copies.
  - `art/maps/*.svg` are generated by `tools/build-maps.mjs` (rough.js, deterministic). Edit the
    generator, never the output.
- Phone remote: `tools/present.mjs` is a Node-builtins static server plus an SSE/POST relay guarded
  by a per-run token. `deck/remote/deck-remote.js` loads only when the URL has `?remote=<token>`, so
  the Pages build is a plain static site.
- Top-level `illustrations/` holds candidate images; `git mv` one into `deck/illustrations/` when a
  slide uses it.

## Artwork rule

Audiences may read any visual element as part of the metaphor, so artwork should contain nothing
ambiguous or purely decorative.
